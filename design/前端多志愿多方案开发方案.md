# AtlasIB 前端多方案排课对比与决策视图开发规范 (Harmonizer Multi-Scenario Spec)

> **致 AI 助手 (GitHub Copilot / Cursor):**
> 本文档指导重构 `src/views/HarmonizerView.jsx` 及全局数据流。
> 将原先的“单一大课表”改造为**“多方案决策仪表盘”**：用户通过顶部分段选项卡（Tabs）切换 **1~3 套**排课路线（数量由后端按志愿决定，可能只有 1 套），清晰对比每一套方案**分别满足哪些大学、放弃了哪些大学及原因**。
>
> **与后端对齐的关键点（务必遵守）：**
> - 使用新接口 `POST /api/v1/harmonizer/calculate-multi-scenario`；旧接口 `/harmonizer/calculate`（单方案）保持不变，**本视图不再调用它**，其他页面若在用则不要改动。
> - 后端**没有**“保存/采纳方案”的接口（不存在 `/profiles/{id}/active-scenario`）。“设为我的最终选课案”仅保存在前端本地状态（PlanContext / localStorage），不要请求后端。
> - 所有字段名以第 2 节 TypeScript 类型为准，不要自行臆造字段。

## 0. 接口契约 (Backend Contract)

### 0.1 请求

`POST /api/v1/harmonizer/calculate-multi-scenario`

```ts
interface MultiScenarioHarmonizeRequest {
  program_ids: string[];            // 必填，1~50 个，不可重复；来自已选志愿(购物车) /profiles/{profile_id}/programs
  profile_id?: string;              // 可选 UUID；传入后后端读取档案中的语言设置
  primary_language?: string;        // 可选，默认 中文A
  secondary_language?: string;      // 可选，默认 英语B
  secondary_lang_level?: 'fluent_b_hl' | 'bilingual_a' | 'standard_b_sl' | 'beginner_ab_initio'; // 默认 standard_b_sl
}
```

- 主语言与第二语言不能相同，否则 422。
- 请求中没有学生预估总分字段。

### 0.2 响应

```ts
type ScenarioId = 'plan_max_coverage' | 'plan_focused_cs' | 'plan_euro_pathway';
type WorkloadLevel = 'EXTREME' | 'HIGH' | 'BALANCED';

interface ProgramFitStatus {
  program_id: string;
  university_name: string;
  program_name: string;
  country_name: string;
  flag_emoji: string;
  is_covered: boolean;
  unfit_reason: string | null;      // 未覆盖时为原因文本
}

interface HarmonizeSubjectItem {
  subject_code: string;
  subject_name: string;
  group_number: number;             // 1~6（目前只会出现 1~5）
  level: 'HL' | 'SL';
  target_grade: number;             // 1~7
  is_mandatory: boolean;
  requested_by: string[];           // 要求该科目的志愿名称
}

interface ScenarioPlanItem {
  scenario_id: ScenarioId;
  name: string;
  strategy_tag: string;
  target_ib_score: number;          // 覆盖志愿的最高预估分要求；无覆盖时为 0
  strictest_program: string;        // 无覆盖时为“暂无可覆盖志愿”
  hl_count: number;                 // 3 或 4
  coverage_rate_percent: number;    // 0~100
  covered_programs: ProgramFitStatus[];
  uncovered_programs: ProgramFitStatus[];
  subjects: HarmonizeSubjectItem[]; // 固定 6 门
  strategic_summary: string;
  workload_level: WorkloadLevel;    // hl_count >= 4 时为 EXTREME
}

interface MultiScenarioHarmonizeResponse {
  total_selected_programs: number;
  recommended_scenario_id: ScenarioId;
  scenarios: ScenarioPlanItem[];    // 1~3 套
  universal_warnings: string[];     // 数据完整性/学校开课/4HL 高负荷等通用提醒
}
```

### 0.3 方案规则（前端只需展示，不需实现）

- `plan_max_coverage` 始终存在；`plan_focused_cs`、`plan_euro_pathway` 仅在满足条件时出现，因此 `scenarios.length` 可能为 1、2 或 3。
- `recommended_scenario_id` 为覆盖志愿数最多的方案，必定存在于 `scenarios` 中。
- 每套 `subjects` 恰好 6 门；第 4 组最多 2 门。

### 0.4 错误响应

错误体统一为 `{ "error": { "code": string, "message"?: string, "details"?: any } }`。

| HTTP | code | 前端处理 |
|---|---|---|
| 404 | `program_not_found` | `details.program_ids` 为已不存在的志愿 ID；提示“部分志愿已下架”，并允许从已选列表移除这些 ID 后重试 |
| 404 | `profile_not_found` | 去掉 `profile_id` 重试，或提示档案不存在 |
| 503 | `admission_data_missing` / `ib_subjects_missing` / `ib_subject_level_unavailable` | 提示“后端数据暂不完整，请稍后再试” |
| 500 | `invalid_profile_language_level` | 提示档案语言等级异常，请重新保存档案 |
| 422 | `request_validation_error` | 提示参数错误（如志愿为空/超过 50/语言重复） |

### 0.5 其他需要知会的变更

- `POST /api/v1/diagnose` 现在**返回全部符合条件的专业，不再限制 10 个**；诊断结果列表需支持滚动或“展开更多”，不要假定数量上限。
- 前端域名必须在后端 `CORS_ORIGINS` 中，否则浏览器会 CORS 报错。

## 2. 核心状态与数据绑定设计

在 `HarmonizerView.jsx` 中，管理以下核心状态：

```javascript
// 1. 调用 POST /api/v1/harmonizer/calculate-multi-scenario 的完整响应
//    在 harmonizerApi 中新增 calculateMultiScenario(payload)，body 为 { program_ids, profile_id? }
const { data: harmonizeData, isLoading, isError, error } = useQuery({
  queryKey: ['harmonize_multi', selectedProgramIds, currentProfileId],
  queryFn: () => harmonizerApi.calculateMultiScenario({
    program_ids: selectedProgramIds,
    ...(currentProfileId ? { profile_id: currentProfileId } : {}),
  }),
  enabled: selectedProgramIds.length > 0 && selectedProgramIds.length <= 50,
  retry: false,
});

// 2. 当前高亮选中的方案 ID (默认为后端推荐方案)
const [activeScenarioId, setActiveScenarioId] = useState(null);

// 3. 数据变化(志愿增减)后重置为新的推荐方案，避免指向已不存在的方案
useEffect(() => {
  if (harmonizeData) {
    setActiveScenarioId(harmonizeData.recommended_scenario_id);
  }
}, [harmonizeData]);

// 4. 当前方案对象
const currentScenario = useMemo(() => {
  if (!harmonizeData || !harmonizeData.scenarios) return null;
  return harmonizeData.scenarios.find(s => s.scenario_id === activeScenarioId) 
         || harmonizeData.scenarios[0];
}, [harmonizeData, activeScenarioId]);
```

**状态处理要求：**
- 未选志愿：空状态，引导去添加志愿，不发请求。
- `isLoading`：骨架屏。
- `isError`：读取 `error.response?.data?.error?.code`，按 0.4 节表格展示；`program_not_found` 时提供“移除失效志愿并重试”按钮。
- 仅 1 套方案时：隐藏 Tabs，直接展示该方案详情。
- `harmonizeData.universal_warnings` 非空时，在 Tabs 上方用黄色提示条逐条展示。
- 若 `currentScenario.covered_programs` 为空（`target_ib_score` 为 0），隐藏“预估分底线”徽章，显示 `strictest_program` 文案。

## 4. 采纳方案（仅前端本地，后端无持久化接口）

后端目前没有保存所选方案的接口，**不要**调用 `/profiles/{id}/active-scenario`。“设为我的最终选课案”只保存在前端：

```javascript
// PlanContext 中：保存到 state 并写入 localStorage
const applyScenarioAsActive = (scenario) => {
  const payload = {
    scenario_id: scenario.scenario_id,
    program_ids: selectedProgramIds,
    subjects: scenario.subjects,
    saved_at: Date.now(),
  };
  setActiveScenario(payload);
  localStorage.setItem(`atlasib_active_scenario_${currentProfileId ?? 'guest'}`, JSON.stringify(payload));
};
```

- 志愿列表变化后，已保存方案可能过期：读取时对比 `program_ids`，不一致则提示“志愿已变更，请重新选择方案”。
- 底部“导出规划长图/PDF”为纯前端功能，导出内容取自 `currentScenario`。
